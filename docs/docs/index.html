Prioritizing Content for Search Review

A machine-learning decision-support workflow for identifying pages that should be reviewed first for a possible content action.

Abstract

This study asks which pages should be reviewed first for a possible content refresh using observable search and content signals. A Random Forest was trained using February 2026 feature-window data and evaluated against a simple warehouse-native visibility baseline using a client-grouped test split. The Random Forest achieved Precision@50 of 0.960 compared with 0.000 for the baseline on the chosen March outcome proxy. The model relied most strongly on average GSC impressions and average GSC position in this evaluation. These results provide directional decision-support for prioritizing human review and should not be interpreted as causal evidence that refreshing a page will improve its performance.

1. Introduction / Problem Statement

Content teams often have more pages available for review than they can inspect manually. The practical problem is therefore not simply to identify whether a page is good or bad, but to decide which pages deserve attention first.

This project studies a decision-support approach for the Refresh / Content Opportunity Scoring lane. The research question is:

Which pages should be reviewed first for a possible content refresh based on observable search and content signals?

The model produces a prioritized queue. A human reviewer remains responsible for determining whether the appropriate action is to refresh, expand, protect, prune, monitor, or take no action.

3. Methodology

Target / outcome proxy

The target is based on the March outcome window: March GSC impressions = 0. This is treated as an observed outcome proxy rather than direct proof that a page needs a refresh.

Feature set

Five observable February feature-window signals were used:

  • Average GSC impressions
  • Average GSC clicks
  • Average GSC position
  • Average GA4 sessions
  • Average scroll events

Model

A Random Forest classifier was selected because the task can contain non-linear relationships and interactions between observable search and engagement signals.

Baseline

The comparison baseline is a simple warehouse-native visibility rule based on February average GSC impressions. It provides a transparent reference point for judging whether the model extracts additional signal.

Validation

The evaluation uses a client-grouped train/test split:

Split Rows Clients
Training 264,134 40
Test 39,438 10

Client overlap between training and test was zero. This prevents pages from the same client appearing in both groups.

Leakage check

A deliberate experiment introduced a March outcome-derived feature. The resulting Precision@50 rose to 1.000, demonstrating why future outcome information must not be used as a model feature. The leaked feature was removed from the honest feature set.

Evaluation metric

Precision@50 is the primary metric because the practical decision is to prioritize the first 50 pages for limited human review.

5. Limitations & Honest Framing

The March target is a proxy based on zero summed GSC impressions. It is not a direct label for whether a page needs a content refresh.

A zero March-impressions outcome may also reflect data-availability conditions, so the target should not be interpreted as a direct measurement of content quality or refresh need.

Some feature fields have substantial missingness. In the modeling dataset, average GSC position has 158,293 missing rows, while average GA4 sessions and average scroll events each have 131,711 missing rows.

Precision@50 describes only the highest-priority 50 rows and does not describe the quality of the entire ranking.

Several model scores are tied. Therefore, the exact ordering within a tied group should not be treated as meaningful.

The analysis is observational. It can identify measured and directional patterns and provide decision-support, but it cannot prove that a content action caused improvement, nor can it predict Google's ranking algorithm.

6. Ranked Recommendations

The model output is best interpreted as a review queue. Pages near the top should be inspected earlier because their model scores are higher for the selected outcome proxy.

Priority group 1 — Review first
Inspect high-scoring pages for a possible content action.
Priority group 2 — Secondary review
Inspect pages with moderately high model scores after the first group.
Human decision required
Review search intent, current content, context, and business importance before choosing refresh, expansion, protection, pruning, monitoring, or no action.
Model scores are prioritization evidence, not automatic content instructions.

9. Project Takeaway

The main practical finding is that a transparent machine-learning ranking can provide stronger prioritization than a simple visibility baseline for the selected outcome proxy under the tested client-held-out split.

The strongest model signals were average GSC impressions and average GSC position. The appropriate operational use is to help a reviewer decide where to look first, while retaining human judgment over the final content action.

The result should be treated as a measured experiment rather than a guarantee of future search performance.
